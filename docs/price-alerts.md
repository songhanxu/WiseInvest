# 期望价格与到价邮件提醒

自选列表和实体账户表格均提供「期望价格」列及相同的邮件提醒设置。在同一页面保存收件邮箱，再在标的行输入价格并点击「设置提醒」。两个页面共用收件邮箱；自选与各交易所、现货/合约、多空持仓的目标价独立设置。目标价按该行报价币种存入 PostgreSQL，刷新页面、重启后端仍会保留。

## 触发规则

- 页面只需填写期望价格，统一自动判断涨跌：保存时目标价高于或等于现价，监控 `现价 >= 目标价`；目标价低于现价，监控 `现价 <= 目标价`。修改目标价时重新判断。
- 每分钟读取用户自选或已绑定账户的最新行情；自选提醒无需连接交易所实体账户。关闭网页不影响监控，但后端必须持续运行，Mac 休眠或网络不可用时不能检查。
- 这是每分钟价格采样，短暂触价后立即回落可能不会被观测到；邮件显示检测价格及时间。
- 同一次设置触发后发送一封邮件并停止该条监控，重新保存目标价会重新启用。邮件只包含标的、账户来源、目标价、检测价格与币种，不包含持仓数量、账号密钥或账户总资产。
- 移出自选或持仓、账户解绑、缺失/过期快照、报价不可用或报价币种变化时不触发。设置仍保留，可删除。
- 尚未配置收件邮箱或 SMTP 时可以保存目标价，页面显示等待配置。不会把配置缺失显示成邮件已发送。
- 已认领的邮件提交不会盲目重试。SMTP 发送失败或进程在发送中退出时，页面显示失败/结果待确认；检查配置与收件箱后重新保存目标价即可启用。数据提交已被邮件服务器接受后的 QUIT 错误不算发送失败。

## 后端发信配置

本地填写 `backend/.env`；Docker 填写 `backend/.env.production`，修改后重启后端。

```dotenv
SMTP_HOST=
SMTP_PORT=587
SMTP_USERNAME=
SMTP_PASSWORD=
SMTP_FROM=
SMTP_TLS_MODE=starttls
```

`SMTP_HOST` 为邮箱服务提供商的 SMTP 主机，`SMTP_USERNAME` 是其要求的登录名，`SMTP_PASSWORD` 使用 SMTP 授权码/应用密码或该服务提供的凭证，`SMTP_FROM` 是允许发送的邮箱地址。接收地址在前端设置，不写进共享环境配置。

支持 `starttls`（通常端口 587）和 `tls`（通常端口 465），按邮箱服务商的说明填写。始终校验 TLS 证书，不支持明文发送。SMTP 参数仅留在后端，不返回浏览器；页面只返回服务是否已配置。

## 接口

均需慧投 JWT，严格按当前用户隔离：

- `GET /api/v1/price-alerts`：目标列表、收件邮箱及邮件服务配置状态。
- `PUT /api/v1/price-alerts/settings`：`{"email":"your-mailbox@example.com"}`；空字符串暂停接收。
- `PUT /api/v1/price-alerts`：`{"account_id":"bitget","holding_id":"bitget:spot:rAAPL","target_price":180,"direction":"auto"}`。持仓 ID 应取实际账户接口返回；不会接受其他用户账户或不存在的持仓。
- 自选提醒使用 `account_id: "watchlist"`、`holding_id: "watchlist:市场:代码"`（如 `watchlist:us_stock:AAPL`）。后端从当前用户保存的自选读取并核对标的，使用与自选页面相同的行情来源；移除自选后暂停检测。
- `DELETE /api/v1/price-alerts?holding_id=...`：移除当前用户对应目标。

后端重新读取并核实持仓身份、报价币种与现价，不信任前端传入的标的、币种或现价。每个用户最多保存 100 项目标。数据库使用用户 + 持仓唯一键，修改时递增版本，发送前原子认领，旧版本发送结果不能覆盖修改后的新目标。

## 验证

测试覆盖涨跌阈值、自动方向、一次触发、修改重启、旧版本保护、并发发送认领、无邮箱/无 SMTP、过期行情与币种变化、邮箱头注入、加密 SMTP 收信及退出失败。数据库测试在临时隔离 schema 中验证持久化及用户隔离，不向真实外部邮箱发信。实际外部收信仍需配置你自己的 SMTP 和收件地址后验证。
